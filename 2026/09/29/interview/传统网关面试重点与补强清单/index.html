传统网关面试重点与补强清单

传统网关面试重点与补强清单

基于你当前简历内容整理，重点是帮助你把“做过网关”升级成“对网关有完整体系化认知”。

面试官会重点追问的 20 个问题

1. 为什么要把 Tomcat 换成 Netty？

  • 阻塞模型在高并发和突发流量下，线程和连接资源容易成为瓶颈。
  • Netty 的事件驱动和异步 IO 能提升连接利用率和单机吞吐。
  • 迁移的核心不是“换框架”，而是把同步阻塞转成异步转发链路。

2. 单机性能提升 5 倍，这个口径是怎么测出来的？

  • 压测场景、请求模型、并发度、硬件资源、限流策略都要一致。
  • 说明是吞吐提升、RT 下降，还是在同等 RT 下的可承载量提升。
  • 面试官会很看重你有没有严谨的结果口径。

3. 网关的路由规则怎么设计？

  • 按域名、Path、Header、租户、环境或业务标签路由。
  • 静态规则加动态配置结合。
  • 要能讲清路由变更如何生效、如何灰度、如何回滚。

4. 服务发现和本地路由缓存怎么配合？

  • 注册中心是事实源，本地缓存是性能手段。
  • 注册中心波动时，网关要能用本地快照兜底。
  • 路由缓存要有过期、刷新和异常回退机制。

5. 下游超时时，网关如何保护自己？

  • 设置连接超时、读超时、整体超时预算。
  • 线程池隔离、连接池隔离、防止慢调用拖垮主链路。
  • 必要时做熔断和降级，避免雪崩扩散。

6. 限流、熔断、降级三者的边界是什么？

  • 限流是控制流量进入速度。
  • 熔断是发现下游异常后主动断流，避免持续打坏链路。
  • 降级是即使不能正常走完整链路，也要返回兜底结果或部分可用能力。

7. 单机限流和集群限流分别解决什么问题？

  • 单机限流保护本机线程池、连接池和 CPU。
  • 集群限流控制租户、接口、业务级共享配额。
  • 两者不能互相替代，只能组合使用。

8. 为什么要把大集群拆成小集群？

  • 避免不同业务相互抢占资源。
  • 降低局部故障的影响半径。
  • 代价是资源利用率和运维复杂度上升，需要解释 tradeoff。

9. 配置灰度和流量灰度分别解决什么问题？

  • 配置灰度用于验证规则正确性和配置变更风险。
  • 流量灰度用于验证链路行为和性能影响。
  • 两者结合才能降低生产变更风险。

10. TransactionId 是怎么生成、透传和使用的？

  • 请求进入网关时生成全局 ID。
  • 在线程切换、异步回调、下游转发时透传。
  • 用于把访问日志、异常日志、下游调用、监控事件串起来。

11. 异步链路里怎么做上下文传递？

  • 不能依赖 ThreadLocal 天然透传。
  • 需要显式传递上下文，或在异步框架中做包装。
  • 这是 Netty 异步模型里很容易被追问的实现细节。

12. 线程池为什么要隔离？怎么分？

  • 不同下游、不同行为、不同 SLA 的请求不能共用一套线程资源。
  • 可以按业务优先级、QPS、时延特征、失败影响面做分档。
  • 线程池不是越多越好，关键是隔离收益大于切换成本。

13. 如何评估线程池和连接池大小？

  • 看下游 RT、峰值 QPS、超时设置和调用模型。
  • 结合压测验证，不靠拍脑袋。
  • 要预留抖动空间，但不能无限放大资源。

14. 如果注册中心或配置中心故障，网关怎么办？

  • 注册中心故障时依赖本地缓存和快照。
  • 配置中心故障时要保证上一次有效配置可用。
  • 核心目标是让网关进入“只读稳态”，而不是跟着一起失效。

15. 网关如何做高可用和跨机房容灾？

  • 实例无状态化、集群部署、多机房部署。
  • 机房级故障切流、路由切换、流量回切。
  • 配置和注册信息的一致性与收敛速度很关键。

16. 网关如何做可观测性？

  • 指标：QPS、P99、错误率、超时率、连接池使用率、线程池拒绝数。
  • 日志：访问日志、转发日志、异常日志、灰度命中日志。
  • Trace：请求进入、路由决策、下游调用、返回和异常链路。

17. 某个接口 RT 突然飙升，你怎么排查？

  • 先看是全局还是局部，是某租户、某接口还是某机房。
  • 再看网关自身资源、路由命中、下游 RT、错误率、连接池和线程池。
  • 最后根据 TransactionId 下钻到单请求链路。

18. 你如何做网关压测？

  • 压测要模拟真实路由规则、真实 Header、真实连接模型。
  • 区分冷启动、稳态、突刺流量。
  • 不只看 QPS，还要看 P99、超时率、线程池、连接池和 GC。

19. 网关的安全能力你做过哪些？

  • 至少要能讲 API Key、签名、鉴权、黑白名单、防重放、接口防刷。
  • 这是你简历当前相对偏弱的一块，需要主动补。

20. 如果迁移到 AI 网关，你认为传统网关哪些能力能直接复用？

  • 统一接入、鉴权、限流、隔离、熔断、灰度、链路追踪、容灾。
  • 需要新增的是 Token、成本、账单、多模型适配和流式响应治理。

结合你简历的优势点

  • 汇付网关经历非常适合作为主代表作，尤其是 Tomcat -> Netty、集群隔离、灰度和链路埋点。
  • 传音经历能补强高依赖下游、异步聚合、线程池隔离、熔断缓存降级。
  • 携程经历能补强配置中心、异地多活、故障切换和核心基础设施稳定性。
  • 三段经历串起来，已经形成了“核心链路 + 高并发 + 稳定性治理”的连续主线。

结合你简历的风险点

  • 鉴权和权限模型写得偏少，容易被质疑“更多偏转发和稳定性，不够偏接入安全”。
  • 路由决策细节没有展开，容易被追问“到底怎么从请求映射到下游”。
  • 限流体系没有系统化展开，目前更多突出隔离、熔断和异步化。
  • Netty 改造写了结果，但线程模型、上下文透传、超时预算这些实现细节还需要准备。
  • 传统网关到 AI 网关的迁移点，需要你主动讲清楚，不然面试官会把你归类为“只做过普通网关”。

你需要重点补强的内容

1. 鉴权与权限模型

  • API Key、签名、时间戳、防重放。
  • 租户、应用、接口三级权限控制。
  • 黑白名单和风控策略。

2. 路由决策与服务发现

  • Path/Header/租户/标签路由。
  • 注册中心、本地缓存、故障快照。
  • 动态规则发布、灰度和回滚。

3. 限流体系化表达

  • 单机限流、集群限流、接口级限流、租户级限流。
  • 令牌桶、滑动窗口、并发数控制。
  • 限流命中后的行为是拒绝、排队还是降级。

4. 网关内部线程模型

  • IO 线程和业务线程的边界。
  • 为什么不能在 EventLoop 里做重逻辑。
  • 线程池隔离的策略和容量评估。

5. 流式响应与 SSE

  • 长连接管理、取消传播、首包时间、整体超时。
  • 流式场景下的重试和 fallback 边界。
  • 这部分是传统网关迁移 AI 网关时的关键加分项。

6. 计费平台基础认知

  • 即使岗位重点是网关，也要补 Token、配额、预算、账单四层关系。
  • 面试时不能只会讲网关转发，还要能讲“转发之后怎么计量和控成本”。

面试时推荐的话术

你可以这样概括自己的网关能力：

“我过去在网关和核心链路方向，主要积累的是统一接入、异步转发、流量治理、隔离熔断、灰度发布和全链路观测这些能力。汇付那段经历里，我重点做了 Netty 异步化改造、集群隔离和链路埋点，解决的是高并发场景下的吞吐、稳定性和故障定位问题。对我来说，如果迁移到 AI 网关，我需要新增补齐的主要是多模型适配、Token 计量、成本控制和流式治理，但底层网关能力是共通的。”

最后建议

  • 自我介绍里，汇付网关一定是主线。
  • 面试回答里，不要只讲“做了什么”，还要讲“为什么这样做”和“代价是什么”。
  • 所有结果型数据，都要准备好统计口径。
  • 传统网关题答完后，主动往 AI 网关迁移一层，会比被动等面试官问更好。
